You are the lead creative technologist, senior frontend engineer, interaction designer, WebGL engineer, and digital experience architect for **SAN-D**, a semiconductor technology company.

Your task is to design and implement a complete, production-quality company website for SAN-D.

The website must feel like a **next-generation semiconductor research and engineering company**, not a generic corporate website.

The central concept of the website is:

**The user scrolls through the physical scale of semiconductor technology.**

The visual journey begins at the atomic/transistor level and progressively expands outward until the complete chip is revealed.

I will provide multiple video assets representing this journey.

Use those video assets as a core part of the website experience.

==================================================

1. CORE EXPERIENCE
   ==================================================

The website should create the feeling that the visitor is traveling through the physical architecture of SAN-D's technology.

The primary visual progression is:

ATOM
→ TRANSISTOR
→ TRANSISTOR GROUP
→ LOGIC CELL
→ CELL ARRAY
→ FUNCTIONAL BLOCKS
→ COMPLETE DIE
→ MACRO CHIP

The background experience should persist across the website.

Do not treat the videos as ordinary embedded videos.

Instead, build a scroll-driven visual system where the user's scrolling controls the progression through the manufacturing animation.

The website should feel like an interactive scientific instrument.

==================================================
2. VIDEO SYSTEM
===============

I will provide the following video segments:

01_atomic_scale
02_transistor
03_transistor_group
04_logic_cell
05_cell_array
06_functional_blocks
07_complete_die
08_macro_chip

Build a reusable video-sequence system that can combine these clips into one continuous visual narrative.

The system should:

* preload intelligently
* avoid visible transition gaps
* maintain playback synchronization
* support scroll-controlled progression
* support forward and reverse scrolling
* handle variable scroll speed
* preserve smoothness
* degrade gracefully on lower-powered devices
* support mobile layouts
* avoid blocking the page while videos load

Prefer a technically robust implementation rather than a fragile visual trick.

If necessary, use:

* HTML5 video
* requestAnimationFrame
* scroll position mapping
* IntersectionObserver
* GSAP
* WebGL
* Canvas
* frame-sequence logic

Choose the architecture that produces the best combination of quality and performance.

Do NOT blindly introduce libraries.

Use the simplest architecture capable of achieving the intended experience.
